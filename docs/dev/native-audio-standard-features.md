# Native audio standard features

Standards reviewed on 2026-10-10. Scoped product-capability notes include accepted
updates through 2026-10-18. This document separates the
negotiated product implementation from vendor APIs, unavailable services and
remaining work. Qualification states the tested inputs, builds, platform and limits in
[Native plugin compatibility and qualification](native-plugin-compatibility.md).
The [audio architecture](../architecture/audio-pipeline.md) describes the
canonical execution and authoring boundaries.

Status: **P** actual product path within stated limits; **R** explicit admission
refusal outside that subset; **V** vendor implementation without a product
consumer; **N** absent; **G** accepted/callback path has an unresolved behavior
gap. **S** implemented current product source whose matching complete native
workflow qualification is still pending. **Q** always describes independent qualification, never universal vendor
compatibility. **Perf U** means current source has no completed native release
deadline acceptance receipt in the reviewed evidence. Missing optional interfaces
can be negotiated unavailable; an implemented core callback cannot become correct
merely by calling it optional.

Mandatory/optional roles for all 85 official VST interface entries are retained
in the [VST3 interface inventory](vst3-interface-inventory.md). An interface marked mandatory for a format
wrapper or validator is conditional on acting as that role; Mondrian is a native
desktop host. CLAP stable extensions are negotiated optional families. Their
method/thread/lifetime obligations become binding when exposed or consumed.

## Shared playback shutdown

Media stops completion publication under the original queue lock, then drains
completed work before joining its existing retirement worker. Only completion
payloads that retain foreign Work enter that worker; PCM and closed Core values
consume no additional foreign-owner units. The original 256-unit limit remains.
Four exact regressions remain covered by 108 current ordinary Playback controls
on Windows (default plus validation features); one
ignored actual MMCSS case is excluded. See the [qualification conditions](native-plugin-compatibility.md#current-qualification-summary-2026-10-18).

Native-child observation now uses that same tracker. Once bound, counted, non-clonable
registrars cover the Timeline renderer, current/nested Sessions and held scope
candidates; factories retain no observation domain. A result producer belongs
to the original ProcessOwner and reports only its final Settled/Unconfirmed
state. Missing, foreign or failed registration makes evidence unavailable;
observation never grants DSP or Source permission. Session and parent producer
slots use the existing resource ledger; App/tracker payloads and Arc blocks
remain outside complete Root heap accounting.

The earlier Windows baseline passes Core509, Audio719, Playback105 and App74, plus
two separate actual OS-owner controls. The App set includes real queued typed
refusals and both retired/external renderer-alias lifetimes; it does not prove
legal native handoff. An old mute-test alias is now released before its original
complete-closure assertion. The owned-VST3 Runtime-to-Media pair also passes with
its matching normal Product: an unconfirmed Retiring child now yields incomplete
facts and unresolved ownership, while a Settled child yields complete facts and
resolved ownership. Both gates verify actual Runtime forwarding and the original
child's producer, with the original180s/2s Job limits. Test-only same-HANDLE
cleanup happens after receipt capture and cannot upgrade the original owner's
result. This closes the earlier false-healthy projection, not its cleanup failure.

Cold Playback construction now acquires a counted root from that same Media
tracker before the original Timeline/Runtime builder. A short borrow reaches
fresh VST3 and CLAP probes, factory validation and retained creation; each Session
forks before population and each original ProcessOwner registers immediately
after spawn. Observation failure stays sticky without changing the original
constructor result or DSP/Source admission. Factories and catalogs retain no domain.

Current Windows controls pass Audio725, Playback108 and App76 (909 ordinary),
including ten new controls; Core509 retains its earlier baseline. Four actual
owned-plugin gates pass one VST3 fresh probe, CLAP normal probe, Note Offer and
rejected child registration. The last preserves exact successful probe metadata
without a settlement report. Two additional actual App owned-VST3 controls now
pass installed-catalog construction through the original Timeline/Runtime and
Media prepare. Releasing all renderer aliases yields complete closure; an
external alias retains unresolved
ownership, and its late release cannot rewrite the captured receipt. Both verify
the original Source claim is removed at shutdown. A third App control passes
actual binding Ready delivery through the original Media Idle poll/App handler,
then one original editor action returns NoEditor, clears the queued request and
leaves no outstanding author work, without changing author state or the installed
Source. All three gates and App76 pass after their shared test setup was extracted.
Idle can service
diagnostics/native controls; the tests use no device and dispatch no PCM.
Independent installation/author capture remains unobserved. This does not
prove each cold probe's registration or legal native handoff. The normal Product
and additional integration type check pass; existing App warnings remain,
without strict zero-warning GO.

New counting does not run in physical callbacks, native DSP or steady PCM blocks.
Cold handoff control on the MMCSS producer does take the tracker mutex; that
existing branch also allocates and uses synchronous IPC. Neither its lock wait
nor whole-producer realtime behavior is qualified. Independent catalog discovery
and create_instance, input inspection, Idle Warmup and precompiled Export still
have unobserved construction. Residual Child custody, whole-shutdown100ms and
other platforms remain separate unfinished work. The post-ACK OS-exit observation
window, capped at 100ms, is a host cleanup policy, separate from the audio
processing deadline; its observed failures have not identified the slow teardown stage.

## Qualification and performance interpretation

The owned suites exercise real native workers, main and auxiliary PCM,
parameters/state, render mode and refusal, thread lifecycle, reset/seek/uneven
partitions, canonical signed transport, shared native PDC, author Undo and
saved/fresh project output. Independent C++ layout/signature and actual COM calls
exercise the selected latest SDK interfaces. These are separate correctness and
ABI scopes; test coverage does not establish universal plugin compatibility.

[Native plugin compatibility and qualification](native-plugin-compatibility.md)
records completed receipts and remaining qualification. A pass certifies its
exact source, product, fixture and environment hashes; an earlier pass cannot
certify a changed source/binary pair. Current native release deadline performance
is **not accepted**. The preserved r30 public isolated-worker run found 21
deadline misses across the CLAP/VST3 max64 uneven 8-sample realtime cases at
48 kHz (166.7 microseconds per actual call), with zero PCM mismatches and zero
operation errors. All twenty offline correctness cases passed. Later source
optimizations, MMCSS admission or an 80 ms producer window do not certify this
leaf deadline and do not rewrite those original measurements. Test-profile correctness evidence is separate from release
performance evidence.

The release harness measures the **public process call including parent IPC,
child native DSP and PCM copy**. Any native request preflight IPC at the root
window is part of that timed production path; its round trip must not be exempted
or replaced with stale cached flags. Exclude setup/discovery/reset/warmup, PCM
oracle/input generation and report I/O. It checks independent weighted PCM,
fixed/uneven buffers of 64/128/256/512/1024 frames, p50/p95/p99/max and the exact
realtime deadline `elapsed_ns × sample_rate ≤ frames × 1e9`. Offline throughput
has no invented realtime pass threshold. For 64 frames at 48 kHz the derived
budget is approximately 1.333 ms; the 100 ms crash deadline is not an audio
performance budget. The harness does not itself establish a pass. Device
underrun, simultaneous chains, automation density, foreign allocations, GUI and
independent vendor workloads need their own declared qualification.

Host-owned preparation payload/state/descriptors/Vec capacities, bus buffers and
old/candidate coexistence must be accurately admitted, with shared Arc
allocations counted once. Worker-lane storage now reports its actual fixed
slots/roles, reader and DSP stack reservations and bounded control overlap;
this is a known subset, not the entire native host. Complete nested SDK, COM,
state, descriptor and message lifetimes still require owning visitors and
incremental old/new/temporary peak admission. Bounded shared mappings alone
do not describe that full memory footprint. Unknown third-party heap/RSS and
OS/allocator bookkeeping require a separately described supervised envelope,
not fabricated zero charges.
Typed CLAP scalar parameter-event storage has actual allocator qualification;
sticky deferred native requests, exact root/occurrence admission, same-child
    control/seed and output-quiescent control hold now have source paths. Complete
known-owner candidate installation remains implementation work, including
host-created COM objects retained by plugin references. Bind/seed/ABI success
does not certify that full peak or private DSP continuity. This local storage result does not close the full
native resource contract or establish a realtime deadline pass.

1. Account all known host owners and measure complete release callbacks
   against the derived audio deadline. Preserve the qualified typed scalar-event
   carrier as heterogeneous event admission is added.
2. Consume legal VST restart and CLAP restart requests through typed deferred
   outcomes. Preserve the complete already-admitted processing window; defer
   the next window before nested/sibling DSP or destination mutation.
3. Install non-RT reprepare candidates for the exact occurrence, prepared plan,
