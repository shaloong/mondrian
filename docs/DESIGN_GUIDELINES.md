# Mondrian 设计准则

> 面向专业视频创作工作流的桌面产品设计规范

## 1. 设计北极星

Mondrian 的界面不应是“炫技型 UI”，而应是“让创作内容成为主角的专业工作台”。

我们参考了 Adobe Premiere Pro、Final Cut Pro 以及近年的专业软件设计趋势，最终为 Mondrian 确立以下核心原则：

- 内容优先：预览画面、时间线内容、素材信息永远比容器和装饰更重要。
- 专业密度：允许高信息密度，但必须通过层级、间距和状态管理保持可读性。
- 快速判断：编辑、预览、导出、错误、选中、同步等状态必须一眼识别。
- 稳定可信：视觉语言克制、精确、低噪声，避免“消费级玩具感”。
- 可定制工作区：布局应服务不同任务流，而不是强迫用户适应固定模式。
- 默认深色优先：深色主题是主战场，浅色主题保持一致语义而非另起一套风格。

## 2. 参考产品提炼

### Adobe Premiere Pro 借鉴点

- 工作区按任务组织，而不是按功能清单组织。
- 面板可以重排，适合多步骤后期流程。
- 整体以中性深灰为基底，用有限高亮色表达焦点与状态。
- 高密度信息通过明确分区、标题、边框和激活态来维持秩序。

### Final Cut Pro 借鉴点

- 浏览器、预览器、时间线的主次关系非常清晰。
- 时间线是编辑中心，交互反馈强调“同步感”和“连续性”。
- 工具栏更轻，内容区域更干净，降低了 chrome 对画面的争抢。
- 更强调“沉浸式编辑”，不是让用户一直看见控件，而是让用户始终看懂内容。

### 现代专业软件趋势

- 减少重装饰，增加真实层级。
- 以自适应布局替代死板大面板。
- 以语义 token 驱动主题，而不是在组件里散落颜色值。
- 通过渐进披露降低首次使用门槛，同时保留专业能力深度。
- 强调无障碍、跨语言和多平台字体回退。

## 3. Mondrian 的视觉性格

Mondrian 应当呈现一种“安静、精确、专业、具有少量品牌锋芒”的气质。

- 基调：中性、冷静、偏工业化。
- 情绪：可信、专注、高效，而不是热闹。
- 品牌感：点到为止，不和视频内容抢主角。

设计判断标准：

- 如果一个视觉元素不能提升编辑效率、信息识别或品牌记忆，就应该被弱化或移除。
- 如果一个颜色没有语义，就不应该进入核心工作区。
- 如果一个组件让用户先注意到 UI 而不是素材本身，它大概率过强了。

## 4. 色彩系统

### 4.1 总体规则

- 核心编辑区以中性灰阶为主，避免大面积高饱和色。
- `primary` 沿用当前默认主题的蓝色体系，作为交互高亮和系统主动作色。
- 视频、音频、播放头、成功、警告、错误保留独立语义色。
- Mondrian 品牌联想中的高纯度红/黄/蓝，可用于启动页、空状态、品牌插画、官网物料；不建议进入主编辑 chrome。

### 4.3 用色纪律

- 蓝色只用于“可操作主路径”和“当前焦点”，不要泛滥到所有按钮。
- 红色优先表达错误、录制、危险和播放头，不用于普通强调。
- 绿色只表达完成、可用、健康状态，不承担品牌表达。
- 黄色只用于需要注意但未失败的状态。
- 任何状态都不能只靠颜色表达，必须配合文案、图标或位置变化。

## 5. 布局原则

### 5.1 工作区结构

Mondrian 默认布局建议保持为：

- 顶部：菜单栏与全局命令。
- 左侧：素材库 / 浏览与检索。
- 中央：预览器与传输控制。
- 底部：时间线主编辑区。
- 浮层窗口：导出、首选项、新建项目等任务型界面。

这一布局应持续优化，但不要轻易打破“左找素材、中看内容、下做编辑”的空间心智。

### 5.2 层级顺序

- 一级内容：Viewer、Timeline。
- 二级内容：Library、Inspector、Export 配置。
- 三级内容：状态栏、辅助提示、上下文菜单。
- 四级内容：弱说明、占位文案、诊断信息。

布局上必须确保一级内容拥有最大可视面积，并在窗口缩放时优先保留。

### 5.3 空间密度

- 默认使用紧凑但不拥挤的专业密度。
- 组件间距优先通过 4、6、8、10、12 的节奏组织。
- 需要连续判断的数据型内容允许更紧凑；需要决策和填写的表单型内容应更松。
- 长时间停留的编辑界面应减少厚重边框，改用明暗层级和轻分割。

## 6. 面板级设计规则

### 6.1 顶部菜单栏

- 只放全局行为，不承载高频局部编辑动作。
- 保留桌面专业软件熟悉感，优先遵守平台菜单结构。
- 菜单项文案以任务命名，不以实现命名。
- 快捷键展示必须稳定对齐，形成肌肉记忆入口。

### 6.2 素材库

- 搜索必须常驻且足够显眼。
- 列表 / 卡片视图都应强调“识别速度”，而不是装饰感。
- 缩略图服务于筛选，不要让卡片边框和背景抢过封面图。
- 空状态要明确下一步动作，例如导入媒体、拖放到此处。

### 6.3 Viewer

- Viewer 是视觉焦点，非必要控件应尽量退后。
- 预览画布始终保持最高对比和最低干扰。
- 传输控制要稳定、紧凑、可盲操作。
- 分辨率、代理、缓存等“性能相关设置”要靠近预览控制区，但不打断观看。
- 错误、加载、代理生成等覆盖层要半透明、短文案、居中或贴边，不遮蔽关键内容。

### 6.4 Timeline

- Timeline 是编辑中心，视觉权重仅次于 Viewer，很多情况下应与 Viewer 并列。
- 播放头必须是整个时间线里最强的细线元素。
- 视频轨、音频轨、锁定、静音、可见性等状态要用固定位置表达，不可漂移。
- 吸附、插入、覆盖、选择框等反馈应即时、精确、细而清楚。
- 缩放与滚动行为要优先保证“我知道自己在哪”和“我知道会落到哪”。

### 6.5 导出与设置窗口

- 采用任务流组织：输入源、预设、输出、队列状态、执行动作。
- 表单组之间用标题和留白区分，不要堆满边框。
- 只在关键状态使用成功 / 警告 / 错误色，避免界面五彩化。

## 7. 字体与排版

### 7.1 字体策略

延续当前实现的系统字体回退策略：

- Windows：优先 `Segoe UI` / `微软雅黑`。
- macOS：优先 `SF` / `PingFang`。
- Linux：优先 `DejaVu Sans` / `Noto Sans CJK`。

原因：

- 专业工具首先需要稳定、清晰、跨语言。
- 中英文混排、时间码、路径、素材名都必须自然。
- 不建议为核心工作区引入风格过强的品牌字体。

### 7.2 层级建议

当前 token 已经形成一个合理基线：

- `10px`：说明、次级状态、标签。
- `12px`：正文、列表、表单、默认操作文本。
- `14px`：局部标题、较强操作文本。
- `24px mono`：时间码、大数字、空状态核心提示。

排版原则：

- 标题不要过大，专业软件靠信息秩序而非巨型标题建立层级。
- 数字、时间码、帧号、导出进度优先使用等宽风格。
- 次级说明优先减轻颜色，不优先减小字号。

## 8. 图标与控件

- 图标默认应为单色，跟随文本色，不自带品牌色。
- 工具栏图标必须支持 hover、active、disabled 三态。
- 图标轮廓应偏几何和工程化，避免插画式笔触。
- 默认 14px 图标尺寸适合当前密度，可继续作为基础规格。
- 按钮优先轻量矩形或弱圆角，不做过度拟物。

控件规则：

- hover 通过底色轻微提升，不靠发光。
- active / selected 优先使用底色和边界的双重反馈。
- dropdown、menu、context menu 应保持“轻容器、强可读”风格。
- 危险动作必须和普通动作拉开层级，不可只放在相邻位置。

## 9. 动效与反馈

- 动效应只服务理解，不服务表演。
- 主界面切换建议控制在 `120ms` 到 `180ms`。
- 时间线拖拽、吸附、播放头移动反馈要即时，不使用明显缓动拖泥带水。
- Viewer 播放中应压低非必要动画，优先保障媒体反馈稳定。
- 导入、代理生成、导出等后台任务必须提供轻量但持续的进度反馈。

## 10. 无障碍与国际化

- 深色主题下关键文本和背景必须保持足够对比。
- 禁止只用颜色区分视频 / 音频 / 错误 / 选中。
- 所有关键图标都要能通过 tooltip、文案或位置被理解。
- 中文、英文、日文素材名和路径必须在列表中自然截断，避免布局炸裂。
- 窗口缩放后一级操作不应消失；优先收起次级信息，而不是隐藏主能力。

## 11. Mondrian 专属建议

为了让产品既专业又有自己的辨识度，建议加入以下“只属于 Mondrian” 的控制策略：

- 品牌识别放在启动页、欢迎页、空状态、官网和宣传图，不强压进编辑主界面。
- AI 能力的视觉表达应与普通功能区分，但不能喧宾夺主；建议使用更轻的描边、标签或微弱色片，而不是整块高饱和面板。
- 当用户进入沉浸式编辑时，Mondrian 应表现得像一台可靠的编辑机器，而不是一个会不断打断创作的助手。

## 12. 对当前实现的落地建议

结合 `crates/mondrian-app/src/ui/theme.rs`、`fonts.rs` 和现有面板结构，后续迭代建议优先做这些事：

1. 继续把组件样式收口到 token，而不是散落在面板实现里。
2. 补充更完整的状态 token，例如 `focus_ring`、`overlay_scrim`、`panel_divider_strong`。
3. 为 Timeline、Viewer、Library 建立更明确的面板标题与局部工具区规范。
4. 建立“默认 / 紧凑”两档密度模式，为专业用户留出更高信息密度空间。
5. 为空状态、错误状态、拖放状态建立统一模板，减少各面板各写一套。
6. 在后续 Qt 迁移中保持 token 名称与语义稳定，避免重新发明主题体系。

## 13. 一句话总结

Mondrian 的设计方向应当是：

**像 Premiere 一样专业可扩展，像 Final Cut 一样内容优先，再用 Mondrian 自己克制而锋利的品牌语言收口。**
