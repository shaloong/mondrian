# Domain docs

This is a single-context repository.

## Before exploring

- Read `CONTEXT.md` at the repository root.
- Read the ADRs under `docs/adr/` that touch the area being changed.
- If a referenced document is absent, proceed without creating it pre-emptively.

## Vocabulary

Use domain terms as defined in `CONTEXT.md` in issue titles, hypotheses, tests, and implementation notes. Avoid introducing synonyms for concepts that already have canonical names.

If a needed concept is missing, first determine whether existing vocabulary already covers it. Record a genuine terminology gap for later documentation work.

## ADR conflicts

Surface any proposed change that conflicts with an existing ADR explicitly. Do not silently override an accepted architectural decision.
