# Extension 打包与分发

> **状态：通用平台尚未实现。** 本目录提供现有效果 Extension SDK 资料。
> 正式命名与边界见 [Extension 文档](../README.md)。

## 1. 当前可用的集成方式

源码级 Effect SDK 通过 Cargo 依赖集成，由应用显式注册 EffectDefinition 及其
Contract。它需要编译应用，不是独立安装的第三方 Extension，也不提供安全沙箱。

OpenFX/VST3/CLAP 则通过各自 Adapter 发现和执行用户安装的原生格式插件，
不需要先转换成 Mondrian Extension 包。当前准入、兼容性和分发边界见
[原生格式插件宿主](../../architecture/native-plugin-hosts.md)。

## 2. 未来 Extension 包

一个 Extension 是安装、版本、依赖、启停和移除的单位，可包含：

- 无代码的语言包、主题、图标、预设和其他资源。
- HTML/CSS/DOM 面板及打包后的浏览器 JS；TS 在构建时转换。
- Rust 执行入口，使用经过验证的 WASM 或 OS 沙箱原生容器。
- 上述入口的组合，以及命令、面板、提供者等多种贡献。

清单需要描述稳定身份、版本、宿主/API 兼容范围、贡献、资源、运行入口和目标、
激活条件、依赖以及请求的权限范围。最终字段名、SDK 类型、归档格式、包后缀、
资源 URL scheme 和商店协议尚未决定；目前没有可独立安装的通用 Extension 包协议。

原生依赖只能在已验证的容器与授权范围内使用；包内有 DLL 或 FFI 绑定不意味着
它可以在编辑器进程加载，或自动拥有网络、外部文件及子进程权限。

## 3. 安装、权限与项目依赖

安装信任不等于全部授权。权限声明由用户策略和运行时 broker 转换为具体范围内
的授权；新请求的能力不能沿用无关的旧授权。拒绝、撤销、越界或不受支持的能力
返回明确失败，不回退到无限制执行。

独立分发前必须验证包路径与解包边界、依赖兼容性、完整安装、更新失败恢复、
禁用/移除后的清理以及包与运行身份的对应关系。具体签名和商店方案后置。

项目保存的是稳定定义身份、参数、schema/版本和必要状态，不是已安装包、本机
执行对象或用户授权。缺失、禁用或不兼容时保留作者数据并报告依赖问题。
仅打开项目不会自动授予外部访问、安装或超出当前策略的执行权限。

## 4. Alpha 与兼容

通用 Extension 平台会在较长的 Alpha 阶段允许 API 调整；宿主必须显式检查兼容，
并报告不可用原因。成熟后再按能力提供稳定 API。当前
CURRENT_EFFECT_EXTENSION_API_VERSION 属于效果 SDK，不是通用平台稳定性承诺。

源码 API 和文档统一使用 Extension 命名，不提供旧称别名。已保存的定义 key、
参数身份与项目序列化判别值保持数据契约；原生格式 ABI 仍由各格式定义。

## 5. 交付顺序

先完成预定音视频插件宿主范围，再实施 Extension。先验证无代码资源加载，
首个可执行版本必须包含真正受限的执行容器、统一权限代理和端到端 SDK。
本地开发加载、打包、调试与诊断先于商店；不要求开发者重编译整个应用。

完整阶段和验收要求见
[Extension 交付规划](../../architecture/extension-system.md#rollout-and-evidence)。
