# Extension 实施准备与验收计划

> **状态：规划，尚未开始实施。** 本文把已接受的方向对应到当前代码入口与后续交付。
> 先完成预定音视频插件宿主范围，再进入以下平台工作。它不是新 SDK、排期或运行时选型承诺。

范围与约束以 [Extension 架构](../architecture/extension-system.md) 和
[ADR 0011](../adr/0011-use-managed-extension-platform.md) 为准。以下代码入口按本次
develop 更新后的源码核对；开始实施时需重新确认，不能把当前内部签名直接冻结为外部协议。

## 2. 工作顺序与退出条件

以下是可审查的工作包，不是已创建的 issue，也不承诺同时推进。

### E0：音视频宿主前置范围收口

由现有音视频工作确定并验证本轮支持范围，涵盖产品接入、参数/状态、实际厂商行为、
原生编辑器、性能、失败恢复与 Preview/Export 一致性。使用现有领域验证与证据，
明确哪些组合已支持、哪些明确拒绝，不要求在开始 Extension 前兼容所有厂商和功能。

**退出条件：** 前置范围有可核验的结果与剩余限制；其项目身份、模型和处理边界已经
足以作为通用平台的输入。Extension 不通过提前抽象规避未解决的领域问题。

### E1：包、身份与无代码资源

先定义最小清单和版本/依赖检查、资源定位、安装/启停与诊断。以外置语言包验证通路，
保留 Fluent 和当前产品回退；资源包无需启动可执行代码。包身份、贡献身份、运行实例
和项目实例分别建模；现有效果 key 不直接作为未来包 ID 的格式约束。

**退出条件：** 不重编译应用即可发现语言包；新增语言、缺失翻译、冲突资源、无效清单、
禁用/更新和重启恢复都有明确结果。独立包加载前已处理解包越界、部分安装与归属问题。

### E2：执行容器与权限技术验证

在承诺 SDK 兼容面之前，对真实 Web 环境和 Rust 候选容器做最小验证。使用同一组文件、
网络、子进程/伴随应用和跨扩展访问场景，分别证明已有授权可执行、拒绝/越界无法绕过。
Rust 原生 Worker 与 WASM 的适配范围分别记录；不把任意 Rust crate 原样可用作为前提。

**退出条件：** 容器实际限制与宿主代理形成完整路径，有直接 I/O 绕过的反向验证；
结果足以选择首个支持的运行目标。某目标无法落实限制时保持不支持，不退回无约束执行。

### E3：公共创作接口、命令与 SDK

先公开足够完成一个真实工具的查询与编辑操作，宿主负责认证调用者、协议转换、授权、
取消与终态。命令菜单、快捷键、扩展和 AI 继续复用领域操作。异步操作捕获并检查
Authoring Session 与作者版本；批量编辑形成一个事务，不让外部请求直接提交内部状态。

**退出条件：** 一个工具能读取有界选择快照、预览操作并以一次 Undo 步骤提交；
项目切换、旧结果、重复响应、无效参数、取消和权限拒绝均不能产生错误的项目修改。
用户已拒绝的权限不会因工具重试而反复弹窗。公共错误与消息有版本和诊断身份。

### E4：真实 Web 面板与工作台贡献

接入 HTML/CSS/DOM 面板，宿主提供停靠、焦点、主题令牌、语言上下文、资源及事件桥接。
面板和命令分别拥有明确身份与生命周期；菜单/工具栏只呈现命令。Rust 若提供 UI 或
Overlay，需使用另行定义的表面协议，不把 Rust Widget trait 对象作为跨二进制 ABI。

**退出条件：** 面板可停靠/浮动、缩放、键盘访问和使用输入法；隐藏、关闭、扩展禁用、
崩溃和重启后的布局恢复行为明确。浏览器网络资源与导航也受策略控制，不只检查 SDK fetch。
零/一/多个面板的体积、启动、内存/GPU 和播放影响经过实测。

E2、E3、E4 可以在实施阶段交替验证，但它们共同构成首个可执行 Extension 版本的门槛。
不能把某一个无权限控制的 UI 演示当作可对外安装的扩展平台。

### E5：更新、依赖与指定实现替换

补齐运行中禁用、版本替换、更新失败恢复和注销；已有任务和领域处理结果按其所有者的
生命周期退役。保留项目作者数据及必要 schema/状态，缺失依赖可诊断、可恢复。
替换点明确多实例/独占规则、用户选择与恢复默认实现的行为。

**退出条件：** 两个扩展竞争同一入口时结果可预测；禁用后不残留可调用命令或失效面板。
旧运行实例的迟到消息不能影响新实例；新请求的权限不自动继承无关旧授权。已有作品
不会因卸载、拒绝授权或升级失败而被静默删改或替换输出。

### E6：逐步扩大公开能力

迁移有代表性的内置功能使用公共接口，再扩展 Inspector、Viewer 工具、Timeline 工具、
素材与交付提供者。完整工作台/编辑器替换、第三方新创作类型和扩展间贡献协议后续分别
设计。新增 Clip Content 前必须明确修改 ADR 0007 及其领域契约，不能先塞入任意对象包。

**退出条件：** 每次增加的能力都有实际使用者和领域验收；公共接口的能力足以服务内置
实现，不靠私有 AppState 通道实现演示。按成熟度逐个稳定 API，Alpha 不提前承诺全面兼容。

## 3. 需要带测量结果回来选择的事项

| 待选择项 | 验证内容 | 形成决定时需要给出的证据 |
| --- | --- | --- |
| 系统 Webview 或随包引擎 | winit/wgpu 嵌入、浏览器能力、平台差异、离线部署与更新 | 下载/安装总成本、冷启动、整个进程树内存/GPU、多面板与播放影响；不只报告主进程或引导安装器体积 |
| Rust WASM 与原生容器覆盖 | 实际库兼容、OS 限制、文件/网络/FFI 与宿主调用 | 每种支持目标的通过/拒绝场景、限制、复制与调用成本；不以加载成功替代隔离证据 |
| 无面板 JS 执行方式 | Worker/独立运行时、生命周期、浏览器库与 Node 依赖差异 | 后台任务成本、可用 API、权限与取消行为；不把 JS/TS 支持等同于全量 Node/npm 兼容 |
| 协议与大数据传递 | 控制消息、有界快照、文件/资源句柄及领域处理通路 | 请求/资源所有权、认证、取消、大小上限与故障恢复；避免逐帧走通用脚本 RPC |
| 授权体验与存储 | 范围、期限、项目/用户策略、升级和撤销 | 已授权无感、拒绝不重复询问、后台不弹窗循环、设置可查可改，以及外部程序的清晰信任边界 |

这些问题目前不阻塞文档，也不通过推测设定固定预算或引擎。若验证发现必须牺牲重要的
平台覆盖、Web 兼容、体积或原生能力，再给出成本收益让产品选择。

## 4. 最小端到端样例

- **语言包：** 只含资源，验证安装、发现、回退、禁用与升级，不启动代码。
- **批量镜头整理工具：** 真实 Web 面板读取选择快照，可从已授权文件/服务获取元数据，
  展示修改预览，再用一个作者事务修改现有对象。拒绝访问发生在提交之前，用户可处理失败；
  已完成的外部读取不会被描述成可由项目 Undo 撤销。
- **指定入口的替代实现：** 让用户选择一个替代面板或提供者，验证多扩展竞争、禁用、
  崩溃及恢复内置实现；它不作为完整 Timeline 编辑器替换已交付的证据。

无可执行代码的第一阶段可以独立验收；可执行样例只有在对应容器、权限、宿主接口和
生命周期均满足约定后才对外称为 Extension 支持。
